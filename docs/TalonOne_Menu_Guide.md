# Talon.One 사이드바 메뉴 가이드

> Talon.One 좌측 사이드바의 주요 메뉴 항목에 대한 개념 정리 및 실무 FAQ

---

## 1. Loyalty Program

Loyalty Program은 **적립 포인트 기반의 고객 보상 체계**를 의미합니다. 멤버십 포인트(예: 항공 마일리지, 백화점 포인트)처럼 구매 행동에 따라 잔액이 쌓이고 소비되는 구조이며, TechStore에서는 기프트카드도 이 Loyalty Program 안에서 카드 잔액으로 관리됩니다.

Talon.One의 Loyalty Program은 포인트를 **어디에 귀속시키느냐**에 따라 두 가지 방식으로 나뉩니다.

---

### 1-1. Card-based (카드 기반)

| 항목 | 설명 |
|------|------|
| **포인트 귀속 주체** | 카드 코드 (예: `MXNM-GIFT-U0JZ-OJC3`) |
| **활용 방식** | 물리적 카드 / QR코드 / 가상 코드 스캔 |
| **프로필 연결** | 선택 사항 (익명으로도 사용 가능) |
| **공유·양도** | 카드 코드를 알면 누구든 사용 가능 |
| **적합한 케이스** | 기프트카드, 오프라인 POS 연동, 카드 공유·선물 |

**TechStore 적용:** 기프트카드가 이 방식으로 구현되어 있습니다. 카드 코드(`MXNM-GIFT-XXXX-XXXX`)가 식별자이며, 특정 고객 프로필에 링크하여 소유권을 명시할 수 있습니다.

---

### 1-2. Profile-based (프로필 기반)

| 항목 | 설명 |
|------|------|
| **포인트 귀속 주체** | 고객 프로필 ID (이메일, 회원 ID 등) |
| **활용 방식** | 앱/웹 로그인 기반 |
| **프로필 연결** | 필수 (인증된 사용자만 사용 가능) |
| **공유·양도** | 불가 (계정에 귀속) |
| **적합한 케이스** | 멤버십 포인트, 등급제(Bronze/Silver/Gold), 장기 고객 유지 |

**차이 요약:**  
Card-based는 카드 자체가 가치를 가지는 **토큰형**이고, Profile-based는 특정 회원 계정에 포인트가 귀속되는 **계정형**입니다.

---

### 1-3. Loyalty Program과 Gift Card의 관계

**Loyalty Program이 곧 Gift Card인가요?**  
→ 아닙니다. Loyalty Program은 **포인트 적립·소비의 규칙과 잔액을 관리하는 틀**입니다. Gift Card는 그 틀 안에서 **Card-based 방식으로 발행된 카드**이며, 카드의 잔액이 포인트(또는 금액)로 관리됩니다.

| 구분 | Loyalty Program | Gift Card |
|------|----------------|-----------|
| **성격** | 포인트 운영 체계 | 카드 형태의 화폐 대체 수단 |
| **발행 주체** | 브랜드 (TechStore) | 브랜드 (TechStore) |
| **사용 범위** | 해당 프로그램 내 | 발급처 내 (Closed-loop) |
| **만료 여부** | 프로그램 설정에 따라 다름 | 카드 설정에 따라 다름 |

---

### 1-4. 자금 세탁(AML) 및 법령 준수 이슈

기프트카드는 **증권에 준하는 가치 이동 수단**으로 자금 세탁에 악용될 수 있다는 우려가 실제로 존재합니다.

#### Talon.One의 역할과 한계
Talon.One은 **마케팅 프로모션 SaaS 플랫폼**으로, 금융기관·선불업자·전자금융업자가 아닙니다.  
따라서 AML·KYC 의무의 법적 주체는 **Talon.One이 아닌, 서비스를 운영하는 사업자(TechStore)** 입니다.

Talon.One이 보유한 보안 인증은 다음과 같습니다:
- **ISO 27001** – 정보보안 관리체계
- **SOC 2 Type II** – 서비스 신뢰성 및 보안 감사
- **GDPR** – 개인정보 처리 규정 준수

#### 한국 법령 기준 (TechStore 운영 시 검토 필요)

| 법령 | 주요 내용 |
|------|-----------|
| **전자금융거래법 (전금법)** | 선불전자지급수단 발행·관리업 등록 기준, 충전금 별도 관리 의무 |
| **특정금융정보법 (특금법)** | 선불업자를 '금융회사 등'으로 포섭 → KYC, STR(의심거래보고) 의무 적용 |

**핵심 포인트:**

- **Closed-loop 기프트카드** (TechStore에서만 사용 가능한 카드): 소액 한도 내에서 KYC 의무 완화 예외 규정이 적용될 수 있으나, 반복 충전·양도 패턴에 대한 모니터링이 강화되는 추세입니다.
- **Open-loop 기프트카드** (범용 결제 가능): 엄격한 AML·KYC 규제 대상이며 TechStore 기프트카드에는 해당되지 않습니다.
- 기프트카드 잔액이 일정 금액 이상이거나, 단기간 내 반복 충전·이전 패턴이 감지되면 금융정보분석원(FIU)에 의심거래보고(STR) 의무가 발생할 수 있습니다.

> [!WARNING]
> TechStore가 기프트카드를 실 서비스로 운영할 경우, **법무팀 및 컴플라이언스 담당자와 전금법·특금법 적용 여부를 반드시 사전에 검토**해야 합니다.

### 1-5. Gift Card 사용 금액의 정산 방법

기프트카드는 회계적으로 **이연 수익(Deferred Revenue/부채)** 으로 처리됩니다. 카드 판매 시점에 현금이 들어오지만 실제 상품/서비스 제공 전까지는 매출로 인식하지 않습니다.

#### 회계 처리 흐름

```
[기프트카드 판매 시]
  차변: 현금 / 결제수단 청구 계정
  대변: 기프트카드 부채 계정 (이연 수익)

[기프트카드 사용(차감) 시]
  차변: 기프트카드 부채 계정 (부채 감소)
  대변: 매출 (수익 인식)

[기프트카드 프로모션 지급 시]
  차변: 판매촉진비 / 마케팅비
  대변: 기프트카드 부채 계정

[기프트카드 미사용 소멸(Breakage) 시]
  차변: 기프트카드 부채 계정
  대변: 기타 수익 (잔여 부채 매출 인식)
```

#### Talon.One을 활용한 정산 프로세스

| 단계 | 방법 |
|------|------|
| **1. 이벤트 데이터 추출** | Talon.One Webhook 또는 API Export로 카드 생성·차감 이벤트를 데이터 웨어하우스에 저장 |
| **2. 발행 내역 대사** | Talon.One의 Active 카드 잔액 합계 ↔ ERP의 기프트카드 부채 계정 잔액 비교 |
| **3. 사용 내역 대사** | Talon.One의 Redeemed 이벤트 ↔ 주문 시스템(POS/e-commerce)의 할인 적용 내역 비교 |
| **4. 미사용 소멸 처리** | 만료된 카드 목록을 Talon.One에서 주기적으로 추출하여 Breakage 수익 인식 |

> [!TIP]
> Talon.One에서 Webhook을 설정하면 카드 생성·잔액 차감·만료 이벤트를 실시간으로 수신할 수 있어 정산 자동화에 활용할 수 있습니다.

## 2. Incentives

Incentives는 Talon.One에서 고객의 행동을 유도하기 위해 제공하는 **모든 혜택·보상의 총칭**입니다. 사이드바에서 **Rewards**와 **Giveaways** 두 가지 하위 항목으로 나뉩니다.

---

### 2-1. Rewards (리워드)

**정의:** 고객이 **특정 행동을 완료한 대가로 적극적으로 잠금 해제하거나 교환하는 혜택**입니다.

| 항목 | 설명 |
|------|------|
| **트리거** | 고객이 로열티 포인트를 소비하거나 특정 등급에 도달 |
| **고객 행동** | 카탈로그에서 원하는 보상을 직접 선택·교환 |
| **예시** | 포인트 5,000점 → 할인 쿠폰 교환, 골드 등급 → 무료 배송 혜택 잠금 해제 |
| **관리 위치** | Loyalty Program 내 Rewards 카탈로그로 구성 |

**핵심:** 고객이 **직접 선택하고 능동적으로 교환**하는 구조입니다.

---

### 2-2. Giveaways (기브어웨이)

**정의:** Talon.One 외부에서 생성된 코드·쿠폰·상품권을 **Giveaway Pool에 미리 업로드해두고, 특정 조건 충족 시 자동으로 지급**하는 방식입니다.

| 항목 | 설명 |
|------|------|
| **트리거** | 캠페인 규칙 충족 시 자동 지급 (예: 특정 금액 이상 구매, 신규 가입) |
| **고객 행동** | 별도 선택 없이 자동 수령 |
| **예시** | 5만 원 이상 구매 시 타사 상품권 코드 자동 발송, 파트너사 프로모션 코드 지급 |
| **관리 위치** | Giveaway Pool에 코드 목록을 업로드하고 캠페인 룰에 연결 |

**핵심:** 코드 풀을 **미리 준비해두고 조건에 따라 자동 배포**하는 구조입니다.

---

### 2-3. Rewards vs Giveaways 비교

| 구분 | Rewards | Giveaways |
|------|---------|-----------|
| **지급 방식** | 고객이 능동적으로 교환 | 조건 충족 시 자동 지급 |
| **코드 출처** | Talon.One 내부 생성 | 외부 생성 후 Pool에 업로드 |
| **고객 선택권** | 있음 (카탈로그에서 선택) | 없음 (자동 지급) |
| **활용 예시** | 포인트 교환 상품, 등급 혜택 | 파트너 상품권, 외부 쿠폰 코드 |
| **재고 관리** | Talon.One 내 규칙으로 제어 | Giveaway Pool의 코드 수량으로 제어 |
